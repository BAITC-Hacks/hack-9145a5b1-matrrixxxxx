# Career Quest · передача дизайна

Дата: 23 сентября 2026. Интерфейс продукта — русскоязычный адаптивный web app.

## Открыть

- Рабочий интерфейс: `dist/index.html` через HTTP, стартовый маршрут `/#/app/home`.
- Figma: https://www.figma.com/design/T9wOCt9FekAskcs62vKeFm
- Точное состояние Figma и идентификаторы узлов: `docs/figma-design-state.json`.
- Figma содержит 12 desktop-экранов, 4 состояния основного сценария, 3 mobile-макета и 5 общих состояний. Foundations: 28 переменных, 5 текстовых стилей, 17 компонентов. Desktop-прототип: 57 переходов и 3 точки старта; проверка не нашла битых целей или переполнений текста в инстансах.
- Старый интерфейс сохранён в `dist/legacy.html`.

Этот дизайн — интерактивный демонстрационный контур с синтетическими данными. Он не выдаёт локальный выбор роли за корпоративную авторизацию. Изменения сохраняются в localStorage данного браузера. Серверный кабинет `workspace.html`, session API и Telegram разработаны параллельно и не подменяются этим контуром.

## Архитектура страниц

Все приведённые маршруты относятся к hash-router основного интерфейса: `/#/…`.

| Раздел | Страницы | Рабочие действия |
| --- | --- | --- |
| Начало | welcome, sign-in, onboarding | Демо-вход в 4 роли, выбор профиля и карьерной цели |

| Личный кабинет | app/profile, notifications, settings | Редактирование и импорт профиля, уведомления, экспорт и сброс демонстрационных данных |
| Настройки | general, notifications, appearance, privacy | Часовой пояс, демопрофиль, светлая/тёмная тема, уменьшение движения, предпочтения каналов |

## Сквозной сценарий

1. Сотрудник открывает рекомендацию и подтверждает запись.
2. Запись появляется в «Моих активностях». Повторная запись не создаёт дубликат.
3. Сотрудник отправляет описание результата (минимум 20 символов) и необязательную HTTP(S)-ссылку.
4. Руководитель видит работу в очереди, добавляет обратную связь и подтверждает либо возвращает на доработку.
5. Только подтверждение добавляет событие прогресса и повышает навык один раз. Готовность пересчитывается по целевым уровням, а не увеличивается фиксированным процентом.
6. У сотрудника обновляются статус, уведомления и история навыков.

При освобождении места первый участник листа ожидания переводится в подтверждённую запись. Действия отмены, архивации, публикации и сброса требуют подтверждения.

## Визуальная система и адаптация

- Navy `#0b1020`, lime `#bbf451`, светлый фон `#f5f7fb`; переменные цвета и размеров в CSS.
- Иерархия: карьерная цель → рекомендуемый шаг → подтверждённый прогресс. Действия имеют один очевидный основной акцент.
- Desktop: постоянная боковая навигация, карточки, таблицы и боковая карточка записи.
- Tablet: более узкая навигация, перестройка сеток и доступный горизонтальный скролл таблиц.
- Mobile: нижняя навигация, выезжающее меню, одноколоночные формы и карточки.
- Светлая/тёмная тема и настройка уменьшения движения действуют в интерфейсе.
- Пустые результаты, ожидание, ошибки, успех, disabled, validation, forbidden и not-found состояния предусмотрены.
- Нативные labels, dialog, семантические заголовки, focus-visible, skip-link, Escape и ограничение фокуса в мобильном меню. Скрытая навигация inert; изменение ширины не уничтожает введённые данные формы.

## Проверки

`node --test test/design-ui.test.js` — 8 тестов:

- Smoke-render 36 разрешённых маршрутов для 4 ролей.
- Ограничения интерфейса по ролям и отсутствующие страницы.
- Экранирование редактируемых значений в фильтрах.
- Сохранение многоролевой аудитории активности.
- Пересчёт готовности и предел 100%.
- Идемпотентность записи и FIFO листа ожидания.
- Skip-link без смены SPA-маршрута.
- Доступность навигации при изменении ширины без перерисовки страницы.

В реальном браузере проверены: desktop, mobile 390/360 px без горизонтального переполнения; запись → отправка работы → подтверждение руководителем; HR-черновик → публикация → восстановление после refresh; поиск и пустой каталог; административные формы; смена темы. Это функциональная и визуальная проверка, не заявление о полной сертификации WCAG или production-безопасности.

## Честные границы текущей версии

- Основной новый интерфейс пока не объединён с session API. Локальные demo-ID не являются серверными записями.
- Настоящие SSO, HRIS и LMS не подключены. UI объясняет необходимые условия; секреты в нём не запрашиваются.
- Навигатор использует прозрачные демонстрационные правила, не внешний LLM.
- Telegram открывается отдельной страницей `telegram.html` и требует реальной серверной записи и работающего backend. Статический хостинг не запускает Node-сервер и планировщик.
- Пользовательские/ролевые guards основного demo UI — удобство демонстрации, не механизм серверной авторизации.
- Email/reminder preferences сохраняются локально, но не отправляют внешние сообщения.
- Figma содержит систему компонентов и репрезентативные desktop/mobile-сценарии, а не отдельный макет каждого технического маршрута.

Следующий интеграционный этап: соединить новый UI с существующим session API, согласовать модель ролей и событий навыков, затем провести end-to-end проверки на тестовом backend. Не загружать персональные данные сотрудников в публичную демонстрацию.
