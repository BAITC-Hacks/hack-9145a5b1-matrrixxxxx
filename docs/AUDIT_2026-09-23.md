# Career Quest — аудит MVP (23 сентября 2026)

## Итог

Проект имеет сильный визуальный employee dashboard и работающие foundation-элементы development API/Telegram, но пока является **single-page demo**, а не безопасным role-based приложением. Первая ценная вертикаль продукта должна быть такой:

```text
SSO → activity session → enrollment → Telegram opt-in → evidence
→ manager review → confirmed progress event
```

## Что проверено

- `node --test test/career-store.test.js` — 7/7 passed;
- `node --check server.js` — passed;
- `node --check CareerQuestRemindBot.js` — passed;
- employee dashboard визуально проверен на desktop и ширине 390px: базовая адаптивность работает;
- `dist/index.html` — фактически обслуживаемый сервером frontend; корневой `index.html` отличается и пока не должен использоваться как источник изменений.

## Критические находки и решение

| Приоритет | Риск | Решение/статус |
| --- | --- | --- |
| P0 | HR mode переключается в браузере без RBAC; нет sign-in и сессии | Запланировано в Task 1: app shell + SSO/mock development boundary + guards |
| P0 | Пункты sidebar только прокручивают single page, URL не меняется | Запланировано в Task 1: маршруты и защищённые role surfaces |
| P0 | Сотрудник вручную задаёт время activity при записи | Запланировано в Task 2: `ActivityTemplate → ActivityOccurrence → Enrollment` |
| P0 | Reminder cron/webhook работали fail-open при пустых secrets | Исправлено: endpoint теперь fail-closed и доступен только в `TELEGRAM_TRANSPORT=webhook` |
| P0 | polling bot и webhook могли конфликтовать | Исправлено: transport явно выбирается через `TELEGRAM_TRANSPORT`; polling bot откажется стартовать в другом режиме |
| P0 | Legacy reminder endpoint принимал произвольные записи без actor | Исправлено: endpoint требует development actor и существующую Career Quest enrollment; production требует SSO вместо dev auth |
| P1 | Нет manager/admin workflows | Запланировано в Tasks 3 и 5 |
| P1 | Два JSON store и отсутствие транзакций | Допустимо только для demo; Task 6 переносит persistence/notification worker в Postgres/outbox |
| P1 | Progress изменяется симуляцией на клиенте | Task 3 отделяет preview от verified progress event |
| P2 | Нет CI, API/E2E/a11y/security tests, observability и deployment workflow | Task 7 |

## Внесённые безопасные изменения

1. `NODE_ENV=production` не допускает `CAREER_QUEST_DEV_AUTH=true`.
2. Webhook mode в production требует `CRON_SECRET` и `TELEGRAM_WEBHOOK_SECRET` уже при старте.
3. `/api/reminders/run` и `/api/telegram/webhook` не работают без нужного transport/secret.
4. Telegram start link стал одноразовым с TTL 24 часа.
5. UI передаёт development actor только в локальном mode; reminder нельзя создать без связанной Career Quest enrollment.
6. JSON save в server стал atomic, но это не заменяет транзакционную БД и не делает два независимых writer-процесса production-safe.

## Обязательные продуктовые решения до production

- подтвердить: Career Quest — внутренний сервис, где основной вход — SSO, а не public registration;
- выбрать primary Telegram mode: webhook в production, polling только локально;
- утвердить data retention, consent и владельца данных;
- выбрать Postgres/queue/SSO provider и migration owner;
- назначить source of truth frontend: до введения build pipeline им является `dist/index.html`.
