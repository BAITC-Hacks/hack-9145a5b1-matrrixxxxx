# Career Quest — аудит MVP (23 сентября 2026)

## Итог

Проект теперь имеет отделённое server-backed рабочее пространство с role-aware маршрутами и отдельную статическую визуальную демоверсию. Первая ценная вертикаль для employee реализована в development-контуре:

```text
demo sign-in → activity session → enrollment/waitlist → calendar
→ explicit Telegram opt-in → evidence → manager review → confirmed progress event
```

## Что проверено

- `node --test test/career-store.test.js test/session-api.test.js test/telegram-links.test.js test/telegram-reminder-bot.test.js test/design-ui.test.js` — 45/45 passed;
- `node --check server.js`, `CareerQuestRemindBot.js`, `dist/workspace-app.js` и `dist/telegram-connect.js` — passed;
- employee flow вручную проверен в браузере: demo sign-in → выбор server-owned session → enrollment → изменение capacity → cancellation → возврат места; browser errors отсутствуют;
- employee workspace проверен на desktop и ширине 390px: базовая адаптивность работает;
- HTTP entrypoint задаётся `server.js`: landing, sign-in, workspace и legacy demo обслуживаются отдельными маршрутами. Прямое открытие HTML не является поддерживаемым production-запуском.

## Критические находки и решение

| Приоритет | Риск | Решение/статус |
| --- | --- | --- |
| P0 | HR mode переключается в браузере без RBAC; нет sign-in и сессии | Исправлено для demo: explicit development auth boundary, mock role selector, role-aware routes и 403/404. Production SSO остаётся Task 6. |
| P0 | Пункты sidebar только прокручивают single page, URL не меняется | Исправлено: server-backed workspace использует отдельные маршруты. |
| P0 | Сотрудник вручную задаёт время activity при записи | Исправлено: запись возможна только на каноническую server-owned session. |
| P0 | Reminder cron/webhook работали fail-open при пустых secrets | Исправлено: endpoint теперь fail-closed и доступен только в `TELEGRAM_TRANSPORT=webhook` |
| P0 | polling bot и webhook могли конфликтовать | Исправлено: transport явно выбирается через `TELEGRAM_TRANSPORT`; polling bot откажется стартовать в другом режиме |
| P0 | Legacy reminder endpoint принимал произвольные записи без actor | Исправлено: endpoint требует development actor и существующую Career Quest enrollment; production требует SSO вместо dev auth |
| P1 | Calendar API мог обойти статус записи | Исправлено: ICS выдаётся владельцу только для `enrolled`/`confirmed` и неотменённой session. |
| P1 | Telegram renewal мог использовать старое расписание, а legacy link мог не иметь TTL | Исправлено: renewal синхронизируется с канонической session; `/start` принимает только валидный будущий expiry. |
| P1 | Legacy Telegram/registration routes расходились с актуальным API | Исправлено: return ведёт в `/app/notifications`, legacy demo ведёт в каталог сессий, opt-in описан как отдельное согласие. |
| P1 | Нет полного manager/admin UI | Частично: review backend есть, отдельные рабочие UI поверх него — следующие Tasks 3–5. |
| P1 | Два JSON store и отсутствие транзакций между bot/scheduler/link-service | Допустимо только для demo; atomic replace не исключает race между процессами. Task 6 переносит persistence/notification worker в Postgres/outbox. |
| P1 | Progress изменяется симуляцией на клиенте | Основа исправлена: review создаёт immutable verified progress event; полный UI review — Task 3. |
| P2 | Нет CI, API/E2E/a11y/security tests, observability и deployment workflow | Task 7 |

## Внесённые безопасные изменения

1. `NODE_ENV=production` не допускает `CAREER_QUEST_DEV_AUTH=true`.
2. Webhook mode в production требует `CRON_SECRET` и `TELEGRAM_WEBHOOK_SECRET` уже при старте.
3. `/api/reminders/run` и `/api/telegram/webhook` не работают без нужного transport/secret.
4. Telegram start link стал одноразовым с TTL 24 часа.
5. UI передаёт development actor только в локальном mode; reminder нельзя создать без связанной Career Quest enrollment.
6. JSON save в server стал atomic, но это не заменяет транзакционную БД и не делает два независимых writer-процесса production-safe.

## Обязательные продуктовые решения до production

- подтвердить: Career Quest — внутренний сервис, где основной вход — SSO, а не public registration;
- выбрать primary Telegram mode: webhook в production, polling только локально;
- утвердить data retention, consent и владельца данных;
- выбрать Postgres/queue/SSO provider и migration owner;
- назначить source of truth frontend: server-backed development app — `dist/workspace.html` + `dist/workspace-app.js`; `dist/index.html` — отдельная статическая visual demo до введения единого build pipeline.
